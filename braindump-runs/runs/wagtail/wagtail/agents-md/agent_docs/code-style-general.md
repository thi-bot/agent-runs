# General Code Style & Formatting

> Language-agnostic formatting and style: blank lines, comprehensions, boolean/control flow, constants, dead code removal, escaping, and idiomatic constructs.

**When to check**: When formatting code or applying general style/idomatic-construct rules across Python, JS, or config.

## Rules

<!-- rule:22 -->
- Sort keys alphabetically in configuration objects, class/object property declarations, and framework value maps (`tsconfig.json` `compilerOptions`, Stimulus `static values`/`targets`) — keeps entries findable and diffs minimal — Alphabetical ordering makes it trivial to spot missing or duplicate keys and shrinks merge conflicts when multiple contributors add entries to the same object or map.
<!-- rule:0 -->
- Remove debug artifacts before committing: ad-hoc output (`console.log`, `print`, `pdb.set_trace`, debug-only branches) and commented-out scratch code — Version control preserves history, so commented-out code is unnecessary; stray debug output pollutes production logs and signals unfinished work. For diagnostics that must remain, use the project's logging facilities (e.g., Python `logging`, not `print`). In Python library/module code, also remove leftover debug prints; when output is intended, use `print(...)` call syntax, and in modules supporting both Python 2 and 3, include `from __future__ import print_function` at the top of the file so `print(...)` behaves identically across versions.
<!-- rule:1076 -->
- Use two blank lines around top-level `def`/`class` and one between class methods — matches `flake8`/Black so lint stays green — PEP 8/Black blank-line conventions are what `flake8` enforces; deviating triggers lint failures on unrelated edits and creates noisy diffs.
  - Never put a blank line right after a `def`/`class` header; cap blank lines inside function bodies at one — avoids `E303`/`E301` failures when editing imports or cleaning up
<!-- rule:326 -->
- Reuse existing helpers and module constants instead of re-deriving values — a single source of truth prevents logic drift — Duplicated computations diverge over time and introduce subtle bugs; keeping one canonical implementation means fixes propagate everywhere and behavior stays consistent across modules.
<!-- rule:814 -->
- Extract repeated literals into named module-level constants at the top of the file — magic strings, numbers, cache keys, UUID namespaces, durations, thresholds, option names, array indices, and parsing offsets. Reference the constant at every usage site. Prevents drift where one copy changes and the others silently don't. — Duplicated literals desync during edits; named constants also give the value a searchable meaning.
<!-- rule:103 -->
- **Never lead with lint/type suppressions** (`eslint-disable`, `stylelint-disable`, `@ts-ignore`). Fix the root violation instead — declare variables before use, remove `_` dangles, define/import missing globals, or bring copied/unlinted files into compliance. When the same readability issue appears in multiple similar constructs in a module, fix them all so the pattern is consistent. Before reaching for a suppression, rebase on latest `main` — the issue may already be fixed upstream. If a suppression is truly unavoidable, use the narrowest rule-specific inline disable, add a comment explaining why, and remove or update it once the violation no longer applies. — Blanket suppressions silently accumulate and hide real bugs; fixing the underlying issue keeps the codebase clean and ensures the whole module is treated consistently rather than patched piecemeal.
<!-- rule:1041 -->
- Format dates/times via `{% human_readable_date %}`, `date`/`localize` with `DATETIME_FORMAT`, or the shared JS date util — hand-rolled formats, raw datetimes, custom `<time>`/tooltip markup, and manually translated dates break localization and i18n — These helpers centralize locale-aware formatting and translation, so reimplementing them per call site drifts across the Wagtail admin UI.
<!-- rule:1252 -->
- Delete orphaned/empty files and scrub all references when removing a module — stale references in configs and ignore files (`.eslintrc.js`, `.eslintignore`, `.prettierignore`) silently break builds and linting. — Orphaned files and lingering references in config/ignore files cause silent failures — leftover entries in `.eslintrc.js`, `.eslintignore`, or `.prettierignore` can mask errors, confuse tooling, or reference nonexistent paths, and hidden/sibling ignore files are easy to miss when cleaning up.
<!-- rule:1309 -->
- Re-audit guard clauses when reusing or refactoring logic: reuse existing guard helpers, preserve required `None` checks, drop unreachable or context-specific conditionals — a guard valid in one context can be a silent bug in another. — Dropped guards (e.g., `None` checks) or inlined checks that only made sense in the original context are a common source of bugs when code is `git grep`'d across modules like Wagtail admin views and templatetags.
<!-- rule:1732 -->
- Use raw strings (`r"\W+"`) or double backslashes (`'\\d'`) so regex backslashes survive the string-literal layer — single backslashes get silently eaten, producing wrong patterns. — Python and JS both interpret `\` in string literals before the regex engine sees it, so `"\d"` in JS becomes pattern `d` instead of `\d` — a silent bug that only shows up as broken matching.
<!-- rule:1317 -->
- Prefer `{k: v for ...}` or `{...}` literals over `dict(...)` wrappers and accumulator `for` loops — more idiomatic and faster — Dict comprehensions and literals are idiomatic Python, avoid the extra `dict()` call overhead, and read more clearly than building up an accumulator across a loop body.
<!-- rule:2152 -->
- Use zero-argument `super()` in Python 3 overrides and forward all args (`super().method(**kwargs)`); for deliberate MRO skips use `super(IntermediateClass, self)`, never a hard-coded ancestor — keeps cooperative multiple inheritance correct and avoids Python 2-style class references. — Cooperative `super()` binds to the instance's MRO dynamically, so zero-arg form plus argument passthrough lets mixins and multiple inheritance chain cleanly; hard-coding a later ancestor breaks that contract and silently drops intermediate classes.
<!-- rule:58 -->
- Write idiomatic conditionals: use `!=` over `not (a == b)`, drop equality checks a relational operator (`>`, `<`) already implies, and use `:=` to bind-and-test a value once or a ternary for simple conditional assignment — fewer intermediate variables means less state to track and fewer bugs. — Merged the related boolean/conditional guidance into three scannable bullets and attached a concrete failure mode (`0`/`""` dropped by truthiness checks) rather than restating the rule. Kept the specific operators and constructs (`!=`, `:=`, `is not None`, ternary) since those are the actionable identifiers.
  - When `None` is a sentinel distinct from other falsey valid values (`0`, `""`), test `is not None` explicitly instead of a bare truthiness walrus — `if x := ...` silently conflates them, causing real values to be dropped.
  - Order simple checks first in multi-part conditions, and extract named predicates or predicate variables when it improves readability and testability.
<!-- rule:2741 -->
- Fully rewrite identifiers, comments, and docstrings when adapting sibling-module code — leftover source names mask real bugs. — Copied code that still references the source entity (stale variable names, TODOs, commented-out calls, wrong docstrings) reads as if it works while actually targeting the wrong object; every remnant must be replaced with the target context's names.
<!-- rule:483 -->
- Avoid mutable defaults (`[]`, `{}`, `set()`) — use `None` and create a fresh object inside the function, or `()` for read-only iterables — A default is evaluated once at definition time, so shared mutable state leaks between calls and across modules (admin panels, `rich_text`, search backends, core models, image formats, tests); `None` + in-body init keeps each call isolated, and `()` avoids a `None` guard when the parameter is only iterated.
<!-- rule:647 -->
- Prefer flat early exits over nested `if`/`elif`/`else` — omit `else:` after branches that `return`/`raise`/`continue`/`break`, dedent the body, and demote `elif` to `if`; nests hide the common path and bury the fallback. Return directly from each branch instead of assigning to a local returned at the end. Drop redundant terminal `return`/`return None` (bare `return` for early exits), but keep explicit `return None` when callers consume it or project style favors intent. Keep an explicit `else` only when the preceding branch falls through (e.g., side effects) rather than terminating. — Flattens nesting so the happy path reads top-down and the surrounding scope stays unindented. Keeping the terminated-branch exception and consumed-return exception avoids breaking callers that check for `None`.
<!-- rule:395 -->
- When a `template`, `partial`, `component`, or `view` loses its last reference, grep the codebase for its path/name, then delete the file and its orphaned assets (`CSS` classes, `JS`, other `templates`) in the same change — stale files and dead styles accumulate fast and rot silently — A single grep confirms zero references before removal; bundling the cleanup prevents orphans from lingering across refactors and keeps `checks.html` and asset audits clean.
<!-- rule:1936 -->
- Resolve every conflict before committing — never leave `<<<<<<<`, `=======`, `>>>>>>>`, or `*.rej`/`*.orig` artifacts in any file (source, `CHANGELOG.txt`, docs). — Conflict markers and patch artifacts break builds, confuse diffs, and can silently hide dropped changes. When resolving, check recent commits touching the same file/lines to preserve newly added attributes or behavior instead of discarding one side. Add `*.rej`/`*.orig` to `.gitignore` where appropriate.
<!-- rule:24 -->
- Prefer `getattr(obj, attr, default)` / `d.get(key, fallback)` for optional values — supplies the fallback once and avoids `hasattr`/membership checks or `try`/`except` duplication — Keeps optional-value handling uniform across `wagtail` modules (core, admin, models, utils, query helpers, templatetags, widgets, side panels) so fallback intent is visible at the call site and contract violations surface early instead of being silently papered over.
  - Use direct `obj.attr` / `d[key]` when the API/helper contract guarantees presence — fail fast instead of masking violations
  - Avoid `getattr(obj, 'attr')` without a default — that's just noisy defensive access, not a fallback
  - In hot paths where the key is almost always present, `try`/`except KeyError` around direct indexing is fine; otherwise `.get()` + `None` check is preferred
  - Match the fallback form to semantics: `getattr(obj, attr, fallback)` fires only on missing attrs; `getattr(obj, attr, None) or fallback` fires on missing *or* falsy values
  - For optional dict keys, use `d.get(key)` / `d.get(key, fallback)` — not `if key in d` branches or `try`/`except KeyError` with a simple default
<!-- rule:341 -->
- Add trailing commas to multi-line parameter/argument lists and collection literals (`list`, `dict`, etc.), then run `make format` (Black) before submitting — the trailing comma keeps Black's wrapping one-item-per-line, so adding or removing an entry produces a one-line diff instead of a re-flow. — Trailing commas pin Black's exploded layout, minimizing diff churn; running `make format` keeps indentation and nesting normalized so reviewers see intent, not formatting.
