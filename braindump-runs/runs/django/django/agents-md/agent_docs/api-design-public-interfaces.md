# API Design: Public Interfaces

> Designing public methods, classes, request/response interfaces, and exposed behavior.

**When to check**: When defining or changing public methods, classes, or request/response interfaces.

## Rules

<!-- rule:1531 -->
- Prefer explicit registries/accessors or direct dependency passing over magic module-level names — Magic top-level naming discovery and transparent proxy/wrapper singletons (as in `django/db` and `django/test` runtime replacement) hide real dependencies, defeat type checkers and IDE navigation, so even trivial renames silently break runtime behavior.
<!-- rule:4828 -->
- Expose an optional `json` param on HTTP request methods that serializes the payload and sets `Content-Type: application/json` by default — callers shouldn't hand-roll JSON encoding or headers. — The `json` param standardizes how JSON bodies are sent across the client, preventing inconsistent `Content-Type` headers and duplicated serialization logic. The docs rule matters because form-encoded patterns silently break for JSON endpoints: readers following them send credentials in the body instead of an `Authorization` header, producing auth failures that are hard to diagnose.
  - Don't document form-encoded auth/token techniques as general solutions — JSON request bodies carry credentials via a header (e.g. `Authorization`), not form fields, so form-only docs mislead users.
<!-- rule:4981 -->
- Name registration methods after the object they register (`register_serializer`, not `register_lookup`) — users guess the API from the noun they already have, and diagnostics/decorators can read the stored name off the class or instance. Store the registered name (e.g., on the class or instance) whenever runtime methods need it for error messages or decorator registration. — Django's own registration APIs follow this pattern across `db/migrations` and `urls`, so callers expect `register_<thing>`; naming after the lookup/action instead forces doc-diving and breaks the "register the object, name the object" intuition.
<!-- rule:5617 -->
- Name boolean policy hooks for the positive action and return `True` when it should occur — callers negate to skip, avoiding double-negative bugs — Positive-action naming with `True`-means-do-it makes the negation at the call site predictable; ambiguous hook docs about conditional `pre_save`/update behavior lead to silent data bugs.
  - Document whether conditional updates or hooks (e.g., `pre_save`) actually run — callers in `django/db/backends/base/schema.py` can't reason about side effects otherwise
<!-- rule:5928 -->
- Implement `__call__` when converting a function into a class — instances stay drop-in callables for APIs expecting a callable (callbacks, Django hooks) — `callable(...)`-style APIs and callback registries only accept objects with `__call__`; without it, swapping a function for a class silently breaks callers that pass the object directly. Docstring placement follows the same logic: the class is what users import and read, so a docstring buried on `__call__` is invisible to `help()`, Sphinx, and IDE tooltips that read the class-level doc.
  - Put the descriptive docstring on the callable class, not on `__call__` — the class is the public interface, so help()/introspection surfaces docs at the class level
<!-- rule:3224 -->
- Logging helpers taking `level`: default to `level=None` and resolve to a valid level (e.g., `logging.INFO`) inside — never pass `None` to the logger — Passing `None` through to logging (as seen in `django/utils/log.py` and `django/test/runner.py`) raises on level comparison and breaks callers; resolving to a concrete `logging.*` level in the helper body keeps the public signature optional while guaranteeing a valid level downstream.
<!-- rule:4749 -->
- In GDAL raster code (`RasterSource`, `vsi_buffer`), treat VSI paths as plain filesystem paths — skip existence pre-checks and special-casing, and let the `open` call surface errors. Document and test `vsi_buffer` for non-VSI-memory rasters in `source.py`, `docs/ref/contrib/gis/gdal.txt`, and the GDAL raster tests. Pre-validation rejects valid VSI paths (e.g. `/vsimem/`) that would otherwise open fine, so only the open operation knows whether a path actually resolves. — This prevents the GDAL raster source from breaking valid VSI-backed rasters while keeping a consistent open/error-handling contract across paths.
<!-- rule:5999 -->
- Put shared-cache save/restore in external helpers, context managers, or services — instance methods that snapshot or monkey-patch an object's own state create fragile APIs that wholesale replace internal registries; confirm the feature is truly needed before adding one. — The rule matters because snapshot/restore on shared caches and unkeyed thread-local/global caches leak or clobber state across concurrent instances, while exposing save/restore as instance methods creates fragile APIs that wholesale replace internal registries; external helpers, per-instance keys, and dedicated temporary cache instances keep that state isolated.
  - Key caches by instance when moving per-instance state (e.g. `URLResolver`) into them — unkeyed thread-locals/globals let instances clobber each other's state.
  - Isolate temporary state by swapping in a dedicated temporary cache instance for its duration — snapshot/restore on the shared cache leaks into concurrent callers.
<!-- rule:4478 -->
- Filter stack frames by `skip_names` (qualname/name prefixes), not file paths or `traceback.extract_stack()` — file-based skipping silently breaks when modules move between packages, while qualified names stay stable across refactors. — File-prefix and `extract_stack()`-based skipping tie callers to the physical layout of the code; the moment a module moves or a package is vendored/renamed, frames that should be skipped no longer match and leak into results. Matching on qualname/name prefixes keeps the filter tied to logical identity.
<!-- rule:5421 -->
- Expose URL parts as `host`, `port`, `userinfo`, and `authority` per RFC 3986 — add these alongside composite accessors like `get_host()` rather than redefining them; changing `get_host()` from `host:port` to `host` silently breaks callers expecting the composite form. — RFC 3986 component vocabulary (`host`, `port`, `userinfo`, `authority`) gives callers unambiguous access to individually addressable parts; overloading composite accessors like `get_host()` to mean `host` alone breaks existing callers that parse `host:port`. Adding new accessors preserves backward compatibility while enabling compliant parsing.
<!-- rule:5867 -->
- Follow argparse conventions for CLI options. Omit redundant `dest` when a long flag like `--name` already implies the destination. Set a descriptive uppercase `metavar` (e.g. `BROWSERS`) on options that take a value. Name raw params in `type=`/action callbacks `value`, not a type-derived name like `string`. — Argparse derives destinations and generates usage/`ArgumentError` text from these conventions. Redundant `dest` is noise, missing `metavar` makes errors like "invalid BROWSERS value" unclear, and type-derived callback param names (`string`) break the uniformity readers expect across options.
<!-- rule:1270 -->
- Materialize both sides in `__eq__` for lazy iterators (e.g., `BaseChoiceIterator` subclasses) — use `list(self) == list(other)` or `zip_longest` with a sentinel `fillvalue`, never `type(other)(self)`, which mis-reconstructs the operand and breaks value equality. — Reconstructing the other operand via `type(other)(self)` produces an object that isn't a faithful materialization, so two logically equal iterators compare unequal — or recurse — while the same check against a `list` passes. Tests like `assertEqual(SimpleChoiceIterator(), SimpleChoiceIterator())` in `tests/utils_tests/test_choices.py` catch this; comparison against built-in sequences alone does not.
<!-- rule:4976 -->
- Route the default/base type-dispatch impl through the same registry as explicit types — a hardcoded fallback hides the dispatch chain (Django `db/migrations`, `db/models` type registries) — Keeps dispatch behavior traceable in one place and consistent across type handlers instead of split between registry and fallback logic.
