# Regression and Edge-Case Testing

> Adding tests that reproduce bugs and exercise boundary conditions: duplicate/colliding identifiers, ordering dependencies, whitespace splitting, transformed model attributes, search/filter composition, loop accumulation, date formatting, documented feature usages, and conditional branches.

**When to check**: When fixing a bug or adding behavior and deciding what regression, edge-case, or boundary tests to add.

## Rules

<!-- rule:5887 -->
- Cover `non_picklable_attrs` changes with async-client tests, concrete `WSGIRequest`/`ASGIRequest` subclasses, and None/absent `__dict__` cases (`tests/requests/tests.py`) — async clients inject attrs like `asgi_request` that sync ones don't, so exclusion-list gaps only surface there. — The async test client injects extra attributes (e.g. `asgi_request`) absent from sync clients, and `WSGIRequest`/`ASGIRequest` may override pickling behavior relative to the base class, so testing only the base class with a sync client can miss attributes that end up in `__dict__` and break unpickling.
<!-- rule:3410 -->
- Regression-test `contrib.postgres.search` and `admin` `search_fields` edits against composition, multi-word terms, and FK/M2M lookups — These paths share queryset construction, and untested interactions — chaining onto existing search expressions, splitting multi-word input, and relational/multi-valued lookups — have broken silently before. Cover them in `tests/postgres_tests/test_search.py` and `tests/admin_changelist/tests.py`.
<!-- rule:3457 -->
- Test loop accumulators (`|=`/`+=` inside a `for`) with **≥2 contributing items per call** so swapping in a plain `=` would fail the test — single-item tests pass under either operator and hide regressions in accumulators like `refs_window`/`refs_subquery` built by `get_aggregation`. — A loop-accumulation test with only one contributing item cannot distinguish `|=`/`+=` from `=`, so a regression that drops prior refs (in `get_aggregation`'s `refs_window`/`refs_subquery`, or any similar accumulator) slips through. Requiring multiple items — and both qualifying and non-qualifying inputs — forces the accumulated state to actually matter and catches downstream consumers (e.g. `Q` annotation filtering through window functions). Pre-populating accumulator dicts from the input data keeps qualifying vs. non-qualifying paths from being accidentally tangled.
    - Cover both qualifying and non-qualifying inputs, and populate accumulator dicts from the input data before iterating.
    - In Django ORM aggregation/window tests (`tests/aggregation/tests.py`), stack multiple window/subquery annotations plus a non-window aggregate like `Count('*')` (see `test_referenced_window_requires_wrapping`) so `refs_window`/`refs_subquery` accumulate across more than one ref, and also exercise downstream paths such as filtering a `Q` annotation that refers to a window function.
<!-- rule:82 -->
- Add a test for every new Django branch, guard, or helper (e.g., `select_format` hooks, `restart_with_reloader` in `django/utils/autoreload.py`, `isinstance`/alias guards in `django/db/models/sql/query.py`) — if removing the line doesn't fail a test, it's dead protection; delete it or scope it to the path that actually runs. — Untested guards silently become removable dead code and mask regressions once the flag values or caller paths change.
<!-- rule:3706 -->
- Test collision cases for unique ID generation, not just the happy path — uniqueness bugs only surface when duplicates occur — A uniqueness or mapping bug won't appear until two things collide (e.g. duplicate codenames across different content types). Regression tests must reproduce the collision directly. Don't assume the backend enforces unique constraints — set up the conflict explicitly in a backend-agnostic way, or document/guard the backend dependency.
<!-- rule:1764 -->
- Add regression tests pinning operation order for ordering-dependent fixes — assert the new order passes *and* the old order still fails, so future reorders or reverts can't silently reintroduce the bug — Ordering bugs (resource lifecycle, serialized rollback, test setup/teardown) hide in code that looks correct in isolation; a test that only checks the fixed path won't catch a later shuffle. Asserting both directions pins the invariant.
<!-- rule:701 -->
- Test text splitting/wrapping/whitespace helpers with internal double spaces (e.g. `'foo  bar'`), plus leading/trailing and blank-string inputs — leading/trailing/blank cases pass even when internal whitespace runs are silently collapsed or mis-split. — Text helpers like Django's `django/utils/text.py` and `django/contrib/admin/utils.py` helpers can pass trivial cases while corrupting runs of internal whitespace — the regression tests in `tests/test_utils/text.py` and `tests/admin_utils/tests.py` need to pin down that behavior.
<!-- rule:3252 -->
- Assert on the transformed model attribute or annotation, not the original input/fixture values — e.g. after `Trunc` or converting a `DateTimeField` to a `TimeField`, check the resulting field. Asserting on the input is tautological: it re-tests value construction and never exercises the transformation logic or locks in the behavior/bug fix you're targeting. — When a test creates a model and then annotates, transforms, or truncates/converts its fields, asserting on the original input variable only re-tests construction of that input. Asserting on the resulting transformed attribute or annotation exercises the transformation logic and locks in documented behavior or bug fixes.
<!-- rule:4680 -->
- Cover each documented usage of a new feature with its own test — enumerated entry points (`alias` ordering, whole-tuple lookups, mixed function/column index expressions) each need both creation and expression/ordering assertions; paths documented but untested ship broken — The rule targets features with enumerated usage forms (index expressions, alias ordering, whole-tuple lookups), where a single test only exercises one path. Testing each documented case individually — asserting creation and expression/ordering behavior — keeps docs and behavior in sync so untested entry points aren't silently broken.
<!-- rule:403 -->
- Date-formatting changes: extend the existing invalid-specifier list in `tests/utils_tests/test_dateformat.py`; assert `NotImplementedError` for new stubs; cover sibling variants (e.g. `%a`/`%A`) and zero-padding boundaries. — Reusing the shared invalid-specifier list keeps new stubs consistent with existing ones instead of spawning one-off tests. Asserting the exact error (e.g. `NotImplementedError`) for stubs fails loudly when a format is silently accepted. Sibling variants like `%a` and `%A` often regress independently. Isolating the dimension under test (e.g. single-digit zero-padding) avoids blanket assertions that mask which case broke.
