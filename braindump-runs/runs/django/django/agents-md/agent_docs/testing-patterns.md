# Testing Patterns

> Structuring tests, choosing what to test, and writing reliable assertions.

**When to check**: When adding or modifying tests.

## Rules

<!-- rule:3997 -->
- Test every DOM-context branch, asserting emitted IDs/attrs — e.g. `p.datetime` and `fieldset` variants — so uncovered branches can't hide regressions — Production code that branches on DOM context (element nested in `p.datetime`, a `fieldset`, or standalone) emits different IDs/attributes per branch; without a test per branch, a broken branch ships silently.
<!-- rule:5345 -->
- Test `localStorage`-backed admin toggles in `js_tests` with QUnit — cover toggle + read/write; assume `localStorage` works, don't mock it — The real `localStorage` is stable in the QUnit environment, so mocking it adds noise without catching the bugs that matter — broken toggle wiring or missing persistence.
<!-- rule:4203 -->
- Skip SQL NUMERIC precision tests on MongoDB (e.g. `test_roundtrip_integer_with_trailing_zeros`); don't add `quantize()` to the backend to pass them — `Decimal("8")` → `Decimal("8.000")` round-tripping is a SQL NUMERIC artifact, so emulating it in `django_mongodb_backend` adds conversion code MongoDB doesn't need and keeps tests coupled to SQL semantics. — SQL NUMERIC normalization is not something MongoDB has to replicate. Adding `quantize()` in the backend just to satisfy `test_roundtrip_integer_with_trailing_zeros` bakes SQL-specific behavior into the MongoDB layer.
<!-- rule:6390 -->
- Validate fixed-length typed sequences with `len(collection) == N and all(isinstance(x, ExpectedType) for x in collection)` — never `sum(isinstance(x, ExpectedType) for x in collection) == N`, since counting matches only proves N valid elements exist and silently accepts invalid extras like `[1,2,3,4,5,6,'foo']`. — Counting matches confirms the minimum, not the exact shape; the `len(...) == N and all(...)` form also rejects extra invalid elements, catching fixtures or API payloads that drift.
<!-- rule:5861 -->
- Measure timing/timeout, don't assert performance vaguely — unmeasured claims like "does not take forever" give false confidence that a slow path is fine — A test asserting speed without a real timing or timeout check can never fail on the property it claims to verify, so regressions slip through while the suite looks protective.
<!-- rule:996 -->
- Pair changes to contenttypes migration ops in `django/contrib/contenttypes/management/__init__.py` with tests in `contenttypes_tests/test_operations.py` — add cases to `ContentTypeOperationsTests` mirroring `test_content_type_rename_conflict` and `test_missing_content_type_rename_ignore`, since edge cases like rename conflicts and missing content types silently regress otherwise. — The operation logic and its tests are always co-updated in this project; mirroring the existing `ContentTypeOperationsTests` patterns keeps coverage of conflict and missing-content-type edge cases that aren't exercised elsewhere.
<!-- rule:1106 -->
- Provide a regeneration script for committed test baselines and document its workflow in contributing docs — stale baselines otherwise block contributors and cause silent failures. — Committed baselines (e.g., accessibility checker snapshots) drift as code changes. Without a scripted, documented regeneration path, contributors either hand-edit baselines (unreliable) or let tests fail on unrelated changes, eroding trust in the baseline suite.
<!-- rule:3790 -->
- Test each request-handler termination path — normal completion, client disconnect, parent-task/`ASGI` shutdown — and assert the matching finish signal fires; fail the test on a missing signal. Untested exit paths silently skip cleanup in production. — Without a test that exercises every handler exit path — normal return, client disconnect, and ASGI/parent-task shutdown — a path that never emits its finish signal goes unnoticed until production, where the missing signal silently skips cleanup such as resource release and telemetry finalization.
<!-- rule:3987 -->
- Add partials tests to `tests/template_tests/syntax_tests/test_partials.py`; render with `engine.render_to_string()` and assert rendered sections via `assertIn()`. — Without a single integration test file exercising `engine.render_to_string()` across `template_name#partial_name` resolution, inline/nested `{% partialdef %}` and `{% partial %}`, and missing-partial `TemplateDoesNotExist`, changes in `django.py`, `defaulttags.py`, or `utils.py` can silently break partial rendering or error handling while each module's isolated tests still pass.
  - Rationale: partial behavior spans `django/template/backends/django.py` (`template_name#partial_name` resolution, `partial.engine`), `django/template/defaulttags.py` (`{% partialdef name inline %}` / `{% partial name %}`), and `django/template/utils.py` (`PartialTemplate.find_partial_source()`); one fixed test file keeps name resolution, nested definitions, and missing-partial `TemplateDoesNotExist` coverage from scattering across suites.
<!-- rule:6024 -->
- In `js_tests/admin/DateTimeShortcuts.test.js`, call `DateTimeShortcuts.escapeFormat(format)` from `DateTimeShortcuts.js` instead of reimplementing date-format escaping, and drive regex callbacks with realistic specs (`%d`, `%B`, `%Y`) plus varied whitespace and escape chars — duplicated escaping logic silently passes even when production behavior drifts. — Tests that reimplement escaping test the copy, not production; using the real helper with realistic specifiers catches regressions in `DateTimeShortcuts.escapeFormat` before they reach the admin.
<!-- rule:2697 -->
- **Add regression tests when changing Django admin pagination/ARIA markup** (`admin_list.py`, paginated UI components) — locks in the accessible nav contract so a11y regressions fail CI — The accessible nav contract for Django admin pagination is easy to break silently when editing the pagination templatetag or ARIA markup. Asserting the structure (<nav> wrapper, labelled nav, single aria-current button with correct href) makes accessibility regressions fail in CI instead of shipping unnoticed, and the same contract applies to any paginated UI component.
    - Page buttons must be inside `<nav>`
    - `<nav>` must have a descriptive accessible name (e.g. `aria-labelledby`)
    - Exactly one page button must have `aria-current="page"` with the expected `href`
<!-- rule:4938 -->
- Put environment detectors like `is_fips_mode` in `cache/utils.py`, not tests — mock `cache.utils.is_fips_mode` with subtests for both outcomes; branching on real system state makes tests pass or fail based on the host's FIPS config instead of code behavior. — Environment-detection helpers such as `is_fips_mode` belong in a production utility module (`cache/utils.py`) so both production and test code reference the same implementation. Tests that branch on real system state are non-deterministic — they pass or fail depending on the host's FIPS configuration rather than the code under test. Mocking `cache.utils.is_fips_mode` and driving both mocked outcomes through subtests covers both branches reliably on any machine.
<!-- rule:5698 -->
- Add tests for the concrete edge-case tags from review (`i-mingo`, `de-CH-1996`, `de-1996`, `kl-tunumiit`) whenever you change the language-code regex in `django/utils/translation/trans_real.py`. — The regex change lands in `trans_real.py` but the intended match/reject behavior only lives in the reviewer's head — without these fixtures, a more-restrictive regex silently regresses tags like `kl-tunumiit` or `de-CH-1996` and no test catches it.
<!-- rule:6128 -->
- Add a regression test for conditional signal connections in `Field.contribute_to_class`. — Makes the negative branch explicit — without it, fields that should skip the connection (as in `django/db/models/fields/files.py`) silently regress and the skip logic goes untested. Mirror the pattern in `tests/model_fields/test_imagefield.py`.
<!-- rule:4765 -->
- Fix WKB edge-case failures in `WKBWriter`, not test expectations — Empty geometries and varying SRID values reflect real serialization cases, so relaxing test expectations would hide writer bugs. Match existing GEOS serialization fix patterns in project commit history.
<!-- rule:5830 -->
- Cover `AND`/`OR`/`XOR` connectors in both negated and non-negated states, with aggregate and non-aggregate children, when changing `may_need_split` or `WhereNode.split_having()` — connector/negation combinations silently break `django/db/models/sql/where.py` aggregation splitting, especially when extending splitting to a new connector. — The connector-splitting matrix in `WhereNode.split_having()` (`django/db/models/sql/where.py`) has non-obvious interactions between connector type, negation, and aggregate children. Regressions only surface for the exact (connector, negated, aggregate) combination affected, so changes that don't exercise the full matrix can ship silent `HAVING`-clause bugs.
<!-- rule:4623 -->
- Add a `tests/cache/tests.py` regression test when changing cache-key generation in `django/utils/cache.py`: build requests with same-value `Vary` headers under different names, one counterpart absent, and assert keys differ — guards against key collisions from header-name-insensitive hashing. — Cache-key generation in `django/utils/cache.py` historically collapsed same-valued `Vary` headers regardless of name, which caused responses to share keys incorrectly. A paired regression test in `tests/cache/tests.py` catches this when the utility is refactored, since the two files are updated together.
